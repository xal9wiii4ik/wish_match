# WishMatch — Frontend

Веб-клиент для платформы **WishMatch**: находите людей, которые разделяют ваши
желания, рядом с вами. Свайпайте желания, смотрите их на интерактивной карте по
координатам и собирайте совпадения.

Стек: **React 19 + TypeScript + Vite**, **React Router**, **TanStack Query**,
**Zustand**, **React Hook Form + Zod**, **Tailwind CSS**, **Leaflet
(react-leaflet)**, **Framer Motion**.

---

## Быстрый старт

```bash
cd frontend
npm install
cp .env.example .env   # при необходимости отредактируйте
npm run dev
```

Откройте `http://localhost:3000`.

При запуске через `npm run dev` приложение по умолчанию работает в
**демо-режиме** (`VITE_USE_MOCKS=true`): желания, совпадения и профиль берутся
из встроенного набора данных, поэтому карта, лента и свайпы работают без
поднятого backend. В `docker-compose` мок-слой выключен
(`VITE_USE_MOCKS=false`) — фронтенд обращается к реальному backend.

## Переменные окружения

| Переменная             | По умолчанию            | Описание                                                                 |
| ---------------------- | ----------------------- | ------------------------------------------------------------------------ |
| `VITE_API_BASE_URL`    | `""`                    | База API. Пусто → используется dev-proxy на `/v1`.                        |
| `VITE_DEV_API_PROXY`   | `http://localhost:8000` | Куда dev-сервер проксирует запросы `/v1`.                                |
| `VITE_USE_MOCKS`       | `true`                  | Вкл/выкл встроенный мок-слой доменных эндпоинтов.                         |
| `VITE_DEFAULT_MAP_LAT` | `55.751244`             | Широта центра карты по умолчанию.                                        |
| `VITE_DEFAULT_MAP_LNG` | `37.618423`             | Долгота центра карты по умолчанию.                                       |

## Подключение к реальному backend

Фронтенд заточен под backend ветки `dev`: auth, профиль, категории, желания,
свайпы и совпадения. Слой `src/lib/dto.ts` приводит wire-формат backend
(`{ lat, lon }`, плоские `user_id`/`category_id`) к доменной модели фронтенда
(`{ latitude, longitude }`, `Wish`, `Match`, `User`).

Чтобы переключиться на реальный backend при локальной разработке:

1. Поднимите backend на `http://localhost:8000`.
2. Установите `VITE_USE_MOCKS=false` в `.env` (в Docker уже выключено).
3. Разрешите CORS для `http://localhost:3000` (`CORS_ORIGINS=["..."]`) — либо
   используйте nginx-прокси из `docker-compose`, где CORS не нужен.

### Используемые эндпоинты backend (`dev`)

| Метод и путь                   | Назначение                        |
| ------------------------------ | --------------------------------- |
| `POST /v1/auth/register`       | Регистрация                       |
| `POST /v1/auth/login`          | Вход (JWT)                        |
| `GET /v1/auth/confirm-email`   | Подтверждение почты               |
| `GET /v1/users/me`             | Текущий пользователь              |
| `PATCH /v1/users/me`           | Обновление профиля                |
| `GET /v1/categories`           | Список категорий                  |
| `GET /v1/wishes/feed`          | Лента рядом (нужны `lat`/`lon`)   |
| `GET /v1/wishes/my`            | Мои желания                       |
| `GET /v1/wishes/{id}`          | Желание по id                     |
| `POST /v1/wishes`              | Создать желание                   |
| `PATCH /v1/wishes/{id}`        | Обновить желание                  |
| `DELETE /v1/wishes/{id}`       | Удалить желание                   |
| `POST /v1/swipes`              | Свайп (like/pass) → совпадение    |
| `GET /v1/matches`              | Список совпадений                 |
| `PATCH /v1/matches/{id}/seen`  | Отметить совпадение просмотренным |

Координаты на backend передаются как `{ lat, lon }` и маппятся в PostGIS
`POINT(lon lat)` (SRID 4326).

### Известные ограничения backend `dev`

- Лента/совпадения возвращают только `user_id`/`partner_id` без профиля
  автора, а эндпоинта `GET /v1/users/{id}` нет — поэтому имя/контакты партнёра
  в реальном режиме скрываются (в демо-режиме показываются полностью).
- Эндпоинта блокировок (`/v1/blocks`) пока нет — список блокировок в реальном
  режиме пуст.

## Docker

Фронтенд включён в корневой `docker-compose.yml` как сервис `frontend`
(multi-stage сборка → nginx):

```bash
docker compose up --build
```

- Фронтенд: `http://localhost:3000`
- Backend (через nginx-прокси `/v1`): тот же origin, проксируется на `app:8000`
- API напрямую: `http://localhost:8000`

nginx отдаёт SPA (с фолбэком на `index.html`) и проксирует `/v1/*` на backend,
поэтому CORS в этой конфигурации не нужен. Переменные `VITE_*` зашиваются на
этапе сборки — переопределяются через `build.args` в compose или
`--build-arg`.

Для production-сборки образа вручную:

```bash
docker build -t wishmatch-frontend \
  --build-arg VITE_USE_MOCKS=false \
  ./frontend
```

## Архитектура

Проект организован по принципу **feature-first**: каждая доменная область
самодостаточна (api / hooks / components / pages).

```
src/
├── app/              # сборка приложения: провайдеры, роутер
├── components/
│   ├── layout/       # каркас, навигация, сплэш-экран
│   ├── routing/      # гварды маршрутов
│   └── ui/           # дизайн-система (Button, Input, Modal, …)
├── config/           # окружение и карта маршрутов
├── features/
│   ├── auth/         # вход, регистрация, подтверждение почты
│   ├── categories/
│   ├── wishes/       # лента-свайпы, CRUD, карточки, форма
│   ├── swipes/
│   ├── matches/
│   ├── profile/      # профиль, настройки, блокировки
│   ├── map/          # Leaflet-карта и выбор точки
│   ├── landing/      # публичный лендинг
│   └── misc/         # 404
├── lib/              # http-клиент, обработка ошибок, гео, утилиты
├── mocks/            # демо-данные и эмуляция backend
├── styles/           # глобальные стили (Tailwind)
└── types/            # доменные типы (зеркало моделей backend)
```

Ключевые решения:

- **Слой API** (`features/*/api`) — единственная точка обращения к сети. Каждый
  метод явно выбирает реальный backend или мок по флагу `VITE_USE_MOCKS`.
- **Серверное состояние** — TanStack Query (кэш, ретраи, инвалидация).
- **Состояние сессии** — Zustand (`useAuthStore`), токен хранится в
  `localStorage`, добавляется в запросы через интерсептор Axios.
- **Маршруты** — ленивые (code-splitting), защищены гвардами `RequireAuth` /
  `RedirectIfAuthenticated`.

## Соглашение об именовании

По требованию проекта используется `snake_case` для переменных и обычных
функций. Исключения продиктованы экосистемой React и обязательны для корректной
работы инструментов:

- **Компоненты** — `PascalCase` (требование JSX).
- **Хуки** — `useCamelCase` (требование `eslint-plugin-react-hooks` и
  React-тулинга).
- **Типы и интерфейсы** — `PascalCase` (конвенция TypeScript).

Всё остальное (локальные переменные, обработчики, хелперы, поля объектов) —
`snake_case`.
